# 幕间 · 推演规则

这份规则描述**推演层**代码实际执行的判定。实现位于 [`src/rules/checks.ts`](../src/rules/checks.ts)，编排顺序位于 [`src/engine/engine.ts`](../src/engine/engine.ts)。

世界层的时间、事件束、事实传播与聚焦场景桥不在本文范围；见 [`WORLD.md`](WORLD.md)。推演结果如何变成有视角、有文体的正文，见 [`PROSE.md`](PROSE.md)。

---

## 1. 一个“时刻”是什么

一个时刻是一次有因果边界的场景单元，不是固定时长。

1. 导演安排处境，并给每位主动角色一段公开处境 + 一段只属于他的私密线索。
2. 主动角色各自宣告一个**举动**：deed（实际做了什么）与 effect（希望达成什么）。彼此看不到对方本刻的选择。
3. 举动全部锁下后，导演为每个 effect 给出 DC、情境修正与落空风险。
4. 如果举动是**敌意**的，并且直接指向某个**主动角色**，目标获得一次**回应**；指向被动角色不进入回应，effect 按 DC 结算。
5. 骰点与总分结算：deed 通常发生；检定决定 effect 是**意外奏效 / 落地 / 落空**。
6. 导演把结果写成公开叙事，结算状态、记忆和事件驱动的时间跳跃。

不是每一刻都过十分钟。可能是三秒、七分钟、半小时；发生什么，决定时间走多远。

---

## 2. 举动：deed 与 effect

每个角色只能宣告一个主要举动。一个举动包含：

- **deed**：可观察的动作、台词或沉默；它通常会发生。
- **effect**：这个举动希望达成/被怎样接住的结果；它不一定发生。
- 主要使用哪项能力；
- 是否使用某个特质；
- 是否指向另一名角色；
- **hostile**：这个举动是否意在强迫、伤害、夺取、逼到角落或欺骗对方；
- 说出口的话（可以为空）；
- 目标、顾虑与风险。

这把“做没做到”和“有没有被接住”分开：

- 陈见月把文件袋拿进屋——这是 deed，发生。
- 母亲有没有看见那张预约单——这是 effect，掷骰决定。
- 陈见月说出“我离婚了”——这是 deed，发生。
- 母亲有没有听进去、有没有接住——这是 effect，掷骰决定。

角色可以撒谎、隐瞒、示弱、威胁、帮助、逃跑、迟疑或观察。`thought` 是内心，不会进入公开叙事。

行动提示词只包含角色可知的信息：自己的角色卡、记忆、欲望、恐惧、秘密，以及公开处境、他人公开资料、自己的状态。导演级真相和其他角色的秘密不进入角色提示词。

## 3. 检定公式

```text
score = d20
      + 能力值（1–10）
      + 特质加值（若选中且与所用能力匹配）
      + 状态修正（仅适用于对应能力的状态）
      + 导演情境修正（−3…+3）
      + 分心/施压惩罚
```

- **d20**：1–20。由 `seed + "action:{时刻序号}:{角色 id}"` 生成，可复现。
- **能力值**：1–10，直接加到总分。
- **特质**：角色主动选择才加值；不适用或幻觉出的特质按 0 处理。
- **状态**：如「右手受伤 −2（影响敏捷）」；总状态修正限制在 −8…+8。
- **情境修正**：−3…+3，不得和能力值重复计价。
- **DC**：导演在看完所有宣告后给出，范围 5–30；遗漏时系统兜底 15。

### 难度刻度

| DC | 含义 |
|---:|---|
| 5–8 | 日常动作：拿东西、倒水、坐下、递东西；失败只带来延误或尴尬 |
| 10–12 | 容易：有基本能力或准备即可 |
| 13–15 | 有真实阻力的情感/关系动作：说真话、请求、拒绝、试探、坚持 |
| 16–18 | 困难：当众承认、改变关系、把秘密放到桌面上 |
| 19–22 | 很大尺度的对抗：战斗、夺物、当众翻盘 |
| 23–30 | 近乎不可能；仍然给分，而不是取消 |

难度由世界、方法、准备、目标和阻力决定，不按角色数值临时加码。

## 4. 结果：意外奏效 / 落地 / 落空

```text
margin = total - target
```

| 结果 | 条件 | 叙事后果 |
|---|---|---|
| **意外奏效** | 自然 20，或 margin ≥ +10 | effect 落地，并获得额外优势、线索、关系位移或控制 |
| **落地** | margin ≥ 0 | effect 落地，通常伴随代价、暴露、消耗或新的压力 |
| **落空** | margin < 0 | effect 没有落地；但 deed 仍然发生：话已说出口、手已伸出、东西已递出，只是没被接住、被岔开、被误解或被挡回 |

系统没有单独的“大失败”。自然 1 不会自动失败，也不额外降灾；仍然按总分和 DC 计算。若举动本身把角色置于明确危险中，导演可以让落空产生相应风险，但不能把普通的落空膨胀成无端死亡。

结果名称只存在于 UI 与机制层。导演写叙事时不报数字、不写“意外奏效 / DC / 检定”。

## 5. 回应：只有敌意举动会触发

若 A 的举动 `hostile=true` 且指向 B，且 B 是主动角色，B 获得**一次回应机会**。回应发生在骰点产生之前。

B 可以选择：

### 继续自己的原举动

- B 的原举动仍然执行。
- B 的原举动与 B 的回应各承受 **−2 分心惩罚**。
- 若有多个敌意举动同时指向 B，B 的回应每多一个再 **−1**。这是同时施压，不是围攻。

### 放下自己的原举动

- B 的原举动 **取消**，不会执行，也不会进行检定；叙事中它表现为被压力打断或自己收住。
- B 的回应不再受分心惩罚。
- 多个敌意举动的施压惩罚仍然适用。

### 对抗结算

- B 的回应只掷一次，用同一个回应总分对抗所有敌意举动。
- A 的总分大于等于 B 的回应总分 → A 的 effect 意外奏效或落地。
- A 的总分低于 B 的回应总分 → A 的 effect 落空。
- 行动者不会因为目标选择继续原举动而受罚；付出分心代价的是目标自己。
- **回应不是额外的免费攻击。** 它决定敌意举动是否落地；若角色在回应里描述反击，反击包含在这次对抗的叙事结果中。

### 非敌意举动

`hostile=false` 的举动——请求、坦白、关心、帮助、礼物、询问、谈判——**不进入单独的回应回合**。目标这一轮自己的举动就是他的回答；effect 的难度由导演按 DC 给出。

这不是说非敌意举动没有阻力；它的阻力是“对方这一轮会做什么、这段关系承受不承受得起”，不是一次格斗式对抗。

## 6. 能力、性格与特质

能力值不是被动属性装饰：

- 高能力代表角色长期信任、惯于依赖的方式。
- 低能力是盲区；角色仍可尝试，但方法和叙事会不同。
- 特质把人物经历转成有限的机械优势，只有在叙事上说得通、角色主动选择时才生效。

### 状态与可见性

- **状态（condition）** 会明确影响对应检定，例如 `右手受伤 −2`、`话没落地 −2`。
- 每条状态有 `visibility`：
  - `public`：旁人能看见，如受伤、湿透、手里拿着什么；
  - `private`：只有本人知道的心情、判断或记忆。
- 情感状态默认 `private`；身体/物件状态默认 `public`。
- **紧张（stress，0–10）** 是叙事气压与上下文，不直接改骰；如果需要机械影响，应落成具名状态。

### 被动角色

角色卡可以写 `"passive": true`。被动角色：

- 不宣告举动，不进入行动提示词；
- 不进入回应回合；
- 仍然在场，仍然有状态、记忆和可被观察的回应；
- 可以被敌意/非敌意举动指向；effect 的 DC 由导演按“对方不主动应对”来评。

一个场景至少要有一位主动角色。

---

## 7. 时间、记忆与状态

- 每个完成的时刻结束后，系统保证每位角色至少得到一条主观记忆。导演可以给出更具体、更私人的版本。
- 记忆有重要性（1–5）与类型（旧事 / 经历 / 隐秘 / 观察）。运行时最多保留约 30 条。
- 公开事实会累积、去重并限制在 30 条内；旧的失效事实由导演移除。
- 状态可新增、移除，影响对应检定。
- 物品可被加入或移除。
- 世界 flags 用 `snake_case` 键记录后续需要追踪的事实。
- 导演的 `private_note` 只并入对应角色之后的记忆与上下文，不会公开。

## 8. 可复现性

每场 run 有一个 seed。举动与回应骰点由 `SHA-256(seed::label)` 确定：

```text
action:{beatIndex}:{characterId}
reaction:{beatIndex}:{characterId}
```

标签里的 `reaction` 是历史命名；它对应的就是“回应”。同一个 seed + 同一举动 + 同一模式会得到相同骰点；叙事文本仍可能不同，因为 LLM 本身不是确定性的。

---

## 9. 失败、重试与断点

每个时刻有阶段：`opening → actions → adjudication → reactions → rolling → resolution → complete`。

- 角色举动并行生成；部分失败时，已完成角色会被保留，重试只补写缺失角色。
- 回应同理。
- 骰点结算后、导演收束失败时，重试不会重掷骰子。
- run 每个阶段都写入磁盘，因此服务重启后可以从中断处继续。
- 如果运行中的服务被杀，下次启动会把 `running` 的 run 标为 `paused`，保留断点。

## 10. 从推演到正文

推演层只负责因果、点数、状态与场面记录。视角、人称、文体、有限视角与主角，由独立的文字创作工作流处理：

```bash
node src/cli.ts --resume <run_id> --prose-only \
  --pov chen_jianyue --person first \
  --style '克制、具体的家庭现实主义' --prose-length medium \
  --prose-out story.md
```

工作流分两步：先把推演时刻整理成场景大纲，再按指定 POV/文体写正文。它只使用视角人物可知的信息，不替人物增加重大决定。详见 [`PROSE.md`](PROSE.md)。

## 11. 收束：世界时钟 + 事后选择，而不是结局条件

`ending` 仍然是 resolution 调用的可选输出；引擎没有“本场核心问题已经回答”的结构化状态，也没有幕形或 `endingCondition`。`maxBeats` 只是停止条件，不是收束条件。

当前做了两件不规定结局的事：

1. **世界时钟**：场景可写 `deadlineClock` 与 `deadlineFact`。到达期限、且没有新的“晚点/停航/取消”公开事实时，引擎把 `deadlineFact` 写入公开事实（例如“末班渡轮在 23:55 离岸”）。这只关闭“还能上船”这个选项，不决定人物赶上、错过还是选择不走；如果人物要延迟，必须在此前建立一个公开的延迟事实。
2. **事后选择结尾**：文字创作工作流的大纲步骤读完全部时刻，选择本场问题第一次得到回答的那一拍作为 `ending_beat_index`，正文只使用到这一拍为止；后面的时刻是未采用的延续。它不发明结局，也不提前规定结局。

实测基线（双人、单地点、单截止时间的《末班渡轮》）在 6 刻内没有产生 `ending`，越过 23:55 后渡轮仍停在渡口；加一条“核心问题已回答即可结束”的提示后，仍跑到 23:59。诊断、改动与复现见 [`CONVERGENCE-TEST.md`](CONVERGENCE-TEST.md)。

所以当前版本不承诺“推演自己停下”；它承诺的是：世界时钟不会让已经离岸的船继续停在渡口，而故事可以在事后从材料里选一个已经出现的结尾。

## 12. 导演的外部事件：也要过骰子

世界事实是**预计会发生**的事，不是不可改变的结局。意外可以改变它；但意外不能由导演随手宣布，否则模型会用“突然起雾/船晚点/电话响了”来拖住剧情。

导演只能在**裁定阶段**提出 `external_events`：

```json
{
  "description": "雾突然变厚，能见度下降",
  "likelihood": "possible",
  "fact": "雾变厚了，渡轮靠岸的速度慢了下来。",
  "reason": "天气变化，独立于任何角色的举动"
}
```

- 每刻最多 1 条，每场 run 总预算 2 条；没有就返回空数组。
- 必须是独立于所有角色行动的客观变化：天气、班次、机械、第三方、事故。不能是某个 deed/effect 的直接结果，也不能是为了“让剧情继续/阻止收束”临时加的新障碍。
- 导演不能给 DC，只能给 likelihood；引擎映射：

| likelihood | DC |
|---|---:|
| routine | 8 |
| possible | 13 |
| unlikely | 18 |

- 如果事件会改变已公开的事实或期限，用 `unlikely`，并额外 +5。
- 引擎掷 `d20`，标签 `external:{beatIndex}:{index}`，自然 20 成功、自然 1 失败；成功才把 `fact` 写入公开事实，失败不写。
- 收束阶段会拿到“世界事件结算（已掷骰）”，**不能新增角色之外的原因**；未发生的事件不能写成发生。`public_facts_add` 只写角色举动/回应直接造成的事实。

这不是角色的检定，没有能力值、特质或状态修正；它是世界层的阻力，防止导演用意外无成本地改写局面。

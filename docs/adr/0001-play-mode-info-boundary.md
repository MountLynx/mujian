# ADR 0001 · 扮演模式的信息边界由服务端裁切

## 背景

扮演模式要求玩家与角色拥有等价的信息边界。可选做法有两种：只在前端隐藏未可知内容，或由服务端返回裁剪后的 run。

## 决定

服务端新增"玩家视图"：`GET /api/runs/:id` 在扮演模式且尚未复盘时，返回裁剪过的 run。前端只渲染这份数据。导出、正文工作流、复盘前的完整 JSON 一律拒绝。

复盘（`POST /api/runs/:id/recap`）一次性解除裁切，并把本场置为 `ended`。复盘不可撤销、不可继续推进。

## 理由

前端隐藏只是 UI 约定，刷新、导出或直接请求 API 都会穿透；"玩家游玩时只能拿到自己能够知道的信息"必须是数据边界，而不是渲染习惯。代价是服务端多一条视图路径，且它必须跟着领域字段演进；测试用"红线标记"扫描返回 JSON，防止新字段无意泄露。

复盘设为终局，是因为一旦看见全部幕后信息，再继续推进就同时破坏了这场游戏的可玩性和已公开信息的因果。复盘后若想看后续，应新建一场。

# 世界层 · 世界-事件模型

世界层不是把局部场景放大，而是在它下面加了一套**时间、因果、信息与调度**。

```text
世界账本与时钟
    │  事件束 / 信号 / 线程
世界导演（World Keeper）
    │  场景契约
聚焦剧场（局部角色引擎）
    │  场景余波
世界账本
```

局部引擎仍然是《幕间》原有的角色行动与骰点系统。世界层决定**什么时候、在哪里、谁被卷进来、谁知道什么**。

---

## 1. 对象模型

| 对象 | 含义 |
|---|---|
| **WorldRun** | 一条独立世界线。包含定义快照、区域/势力/角色运行时、事实、信号、事件、纪元与场景契约 |
| **Epoch** | 世界时间上的一个观察切片。一个纪元可以同时有多个事件束 |
| **Event** | 一组在同一时刻、需要共同写入账本的变化/叙事单元 |
| **Parent Event / Child Event** | 跨区域或同源的联合裁决束。父事件负责协调与总体后果，子事件负责局部事实与场景 |
| **Signal** | 带延迟的信息传递。抵达前不能改变接收者的认知 |
| **Fact** | 客观事实 + `knownBy` 列表。它不是“所有角色都知道的事” |
| **Thread** | 长期剧情线程，包含问题、紧张度和压力钟 |
| **Scene Hook** | 从世界事件里长出来的局部场景契约，交给原有角色引擎 |
| **Scene Run** | 由场景契约生成的本地 run。可整场游玩，再收束回世界 |
| **WorldClock** | 世界开始后经过的分钟数、天数、时间与完整显示 |

世界层刻意没有把“时刻”变成唯一真相。`epoch` 是**提交/观察切片**，事件仍然保留独立身份。

---

## 2. 时间与事件

### 事件驱动的纪元

每次世界推演，世界导演给出：

```json
{
  "advance_minutes": 720,
  "advance_reason": "…",
  "epoch_title": "封灯与密使"
}
```

世界时间从 `startClock` 起算，可跨午夜。没有固定世界轮次，也不要求所有事件耗时相同。

### 并发与合并

世界导演每纪元产生 2–3 个顶层事件束。跨区域共同行动可以组织成父子树。

引擎会检查：**不属于同一棵事件树的两个事件，是否写入同一份状态。**

检查的写集包括：

- 区域状态、区域控制权、各资源键；
- 势力量、合法性、资源、态度、状态；
- 具名角色的位置、状态、紧张、条件、flags；
- 剧情线程的紧张/时钟。

如果两个独立事件写同一字段，解析器拒绝该次输出，并要求模型重试；模型应使用 `parent_local_id` 将它们合并为父事件。

示例：

```text
e0 父事件：白塔诏令与雾港封灯同时发生
 ├─ e1 白塔子事件：次序诏、名字税
 └─ e3 雾港子事件：备用电源被剪、灯室封条
e2 独立事件：铁湾征粮备舰
```

e1 与 e3 在同一个父事件下，即使都触及“归潮准备”线程，也不会被当成独立写冲突；e2 与它们没有共享可写状态，所以可以独立结算。

这不是完整的“世界级事务系统”，但已经比“把所有事件排成一条时间线”更接近真实并发。

### 信号

事实添加时，`known_by` 只列出真正看到/听到/被直接告知的实体。

跨区域消息使用 `signals`：

```json
{
  "to_entity_ids": ["fog_league", "su_he"],
  "channel": "军需官的加密快船",
  "content": "铁湾舰队三日内抵达。",
  "delay_minutes": 720,
  "fact_indices": [0]
}
```

信号在 `arrivesAt` 之前为 `pending`。世界推进到该时间时（在应用本纪元新事件之前）：

- 信号标记为 delivered；
- 携带的事实被加入目标实体的 `knownBy`；
- 时间线上出现一个“讯息抵达”事件；
- 该事实在此前不会出现在目标的知识中。

如果一条信号的目标已经知道它携带的全部事实，引擎会丢弃这条冗余信号；如果只有部分目标不知道，则只向那些目标发送。没有事实索引、只携带一段情报内容的信号仍然会保留。

开局也可以有初始信号。当前预置世界里，白塔的潮汐镜密令在开局即时抵达；铁湾舰队的加密快船在 12 小时后才到。

### 纪元内的事件顺序

所有事件草案都由世界导演在读取 **pre-epoch 账本** 后生成；它不会在生成过程中看到本纪元另一个事件刚刚写下的事实。解析器的写集检查禁止两个独立事件写同一字段，因此它们不会靠“后写覆盖”来互相影响。

应用阶段按模型给出的顺序执行；父子树按深度优先，父事件效果先于子事件。独立事件可以读取彼此不重叠的已应用状态，但不应把这种顺序当成隐含因果。若两个事件确实需要共同决定同一结果，它们应该被组织到同一个父事件下。

## 3. 知识账本

事实是世界的，不是角色的。

```ts
interface WorldFact {
  text: string;
  knownBy: string[];   // actor id / faction id
  public: boolean;
  createdEpoch: number;
  sourceEventId: string | null;
  retiredAtEpoch: number | null;
}
```

- `public` 表示作者设定的全城/全势力级公开信息；创建时会将所有具名角色与势力加入 `knownBy`。
- 势力知道，不等于隶属该势力的每个角色自动知道。角色的认知必须显式出现在 `knownBy` 里。
- 事实不会被硬删除。失效事实保留为 `retiredAtEpoch`，因为角色仍可能记得旧事实。
- 角色档案里的“未知事实”只在剧作家视角显示。
- 世界导演能看到真相；角色引擎只拿自己的事实快照。

当前版本没有独立的“虚假信念”表。事实可以通过未公开、延迟或选择性传播产生信息差，但一个明确记为 rumor/误信的机制仍在路线图中。

## 4. 世界导演

世界导演 Prompt 位于 [`src/llm/worldPrompts.ts`](../src/llm/worldPrompts.ts)。

输入包括：

- 世界概述、地理、硬规则、隐藏真相、导演笔记；
- 当前世界时间与纪元；
- 区域状态、资源、控制势力与交通耗时；
- 势力目标、秘密、力量、合法性、资源、态度；
- 具名角色位置、状态、目标、秘密；
- 剧情线程、紧张度、压力钟；
- 事实账本与 knownBy；
- 仍在路上的信号；
- 最近两个纪元摘要；
- 已收束的聚焦场景；
- 实体 id 清单。

输出包括：

- 时间推进与理由；
- 2–3 个顶层事件（可带子事件）；
- 每个事件的事实、状态变化、信号；
- 一个聚焦场景候选（同区域 2–4 名具名角色）。

聚光角色的重大个人选择不能由世界导演写定。世界导演可以改变他们所在的位置、外部处境、可见信息和别人造成的后果；真正的“现在要怎么做”留给聚焦场景。

### 压力钟

线程的 `clock.value/max` 是**朝 onFill 推进的压力进度**，不是剩余时间。

- 0 表示压力尚未积累；
- 达到 max 表示 onFill 条件成立；
- `clock_delta` 正向推进，负向只用于缓解已经发生的变化；
- 世界导演必须在压力钟满格时处理相应后果。

## 5. 聚焦场景桥

世界事件可能产生一个 `SceneHook`：

```json
{
  "region_id": "fog_harbor",
  "participant_ids": ["shen_yan", ...],
  "question": "谁会先拆开封条？",
  "stakes": "…",
  "public_brief": "…",
  "private_cues": [...]
}
```

点击“开镜”时，引擎：

1. 只取同区域的参与者；
2. 把每个角色已知的世界事实转成个人记忆；
3. 把参与者共同知道的事实装入公共事实；
4. 用世界事件的公开处境作为开场；
5. 创建普通局部 `Run`，挂上 `worldLink`；
6. 保留原角色卡、秘密、特质、能力、关系。

世界世界观的隐藏真相不会被整体注入局部 GM；局部 GM 只拿到一个法律性约束：不得提前宣布世界最终结局。

本地场景结束后可在世界页面或本地场景控制台点击“收束回世界”。收束会：

- 保存一段场景摘要；
- 在世界事实账本中增加一条参与者已知的“聚焦场景”事实；
- 在时间线上增加一个 `scene` 类型事件；
- 让下一次世界导演看到已完成场景，并把余波纳入后续事件。

**世界时间不会因场景内的一刻自动推进。** 一场聚焦场景是对已发生世界事件的局部展开，而不是另一条独立的世界时钟；下一次世界纪元仍由作者手动开启。如果作者在场景收束前已经从世界页面推进了纪元，场景余波会写入当前纪元，视为一次补叙。

只有最新纪元的场景契约可以开镜；旧纪元的未开镜契约会在 UI 中标记为“已归档”，避免用当前世界状态去补一个过去的问题。已经开镜的旧场景仍然可以查看和收束。

## 6. 当前实现的边界

已实现：

- 多区域、多势力、多线程；
- 世界时间与纪元；
- 父/子事件束；
- 独立并发事件的写集冲突检查；
- 事实、knownBy、延迟信号、知识差；
- 纪元时间线、事件档案、角色/势力知识查看；
- 聚焦场景生成、运行、收束回写；
- 世界持久化与断点恢复。

暂未实现：

- 虚假信念/谣言变体（目前只有真相 + 是否知道）；
- LOD 角色的独立日程规划器（当前由世界 GM 直接决定非聚光角色/势力行动）；
- 自动运行的经济、战争、生态过程模拟（压力钟和资源变化目前由世界导演驱动）；
- 多场景同时游玩；
- 地图寻路与移动时间强制校验（交通时间进入提示词，但尚无自动路径规划器）；
- 世界层 LLM 输出的语义忠实度校验（已知问题见 [`ARCHITECTURE.md`](ARCHITECTURE.md)）。

这些不是不可做，而是下一步应该单独成为子系统的部分。

## 7. API

```text
GET  /api/world-presets             预置世界摘要
GET  /api/world-presets/:id         完整预置世界
GET  /api/worlds                    世界线列表
POST /api/worlds                    创建世界 {presetId 或 world, seed, maxEpochs, thinking}
GET  /api/worlds/:id                读取世界（会同步关联场景状态）
DELETE /api/worlds/:id              删除未运行中的世界
POST /api/worlds/:id/advance        启动一个/多个纪元 {mode, epochs}
POST /api/worlds/:id/stop           请求本纪元结束后暂停
POST /api/worlds/:id/scenes         从 scene hook 开镜 {hookId}
POST /api/worlds/:id/scenes/:run/seal  收束场景回世界
GET  /api/worlds/:id/export.md      世界战报
GET  /api/worlds/:id/export.json    完整世界快照
```

世界推进也是异步的：HTTP 只负责启动后台任务，前端轮询世界线状态。

## 8. 预置世界

[`content/worlds/three-tides.json`](../content/worlds/three-tides.json)：

**《归潮王座：三城之夜》**

- 3 个区域：白塔城、铁湾、雾港。
- 3 个势力：白塔潮汐议会、铁湾军府、雾港自由商会。
- 7 名具名角色：沈砚、顾行舟、白露、林小满、苏合、晏无咎、霍廷。
- 3 条剧情线程：三塔同灯、铁湾南下、被撕去的名字。
- 15 条初始事实，覆盖公共知识、地方通告、势力秘密、个人秘密。
- 2 条初始信号：一条零延迟潮汐镜密令，一条 12 小时抵达的加密快船。

世界导演需要遵守的关键硬规则：

- 白塔↔铁湾 36h，白塔↔雾港 48h，铁湾↔雾港 72h；
- 潮汐镜只能传短句，不能传人/传物；
- 被海抹去的名字只能由特定载体保留；
- 世界层不替聚光角色做重大选择；
- 消息必须走路，角色只能依据已知事实行动。
